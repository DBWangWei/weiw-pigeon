Semantic functions currently supported by Pigeon

All 14 public authoring functions for semantic tiers, voice targets, notes, backgrounds, and detours. This documents the current local implementation on codex/semantic-tiers, based on Pigeon 1.0.3; the semantic-tier feature has not yet received a separate release version.

Quick start

Copy the two maintained Typst helpers beside a deck. Import tier helpers under a namespace so they do not collide with existing style names, and import the voice marker explicitly.

#import "pigeon-tiers.typ" as sem
#import "pigeon-sem.typ": pigeon-sem

#set page(fill: sem.background(default: white))

#sem.tiers("result", default: "answer")
#sem.hook[What changes when the sample grows?]
#sem.answer[Sampling variation shrinks; systematic bias can remain.]
#sem.takeaway("message")[More data do not automatically remove bias.]

#sem.answer[
  #pigeon-sem("_table", table(
    columns: (auto, auto),
    [*Source*], [*Effect*],
    [Sampling], [Less variation],
    [Systematic], [Bias can remain],
  ))
]
Ordinary Typst/PDF output
All authored bodies remain visible in normal paint order. Semantic tiers are an additional presentation layer.
Pigeon output
Each configured recipe selects a complete state for the physical page. States are independent; a later state does not automatically inherit an earlier state.

The current maintained helpers are pigeon-tiers.typ and pigeon-sem.typ. The complete runnable example is in examples/semantic-tiers.

The quick start uses the built-in result preset. The eight role names describe content for recipes; they add no colors, fonts, or card decorations of their own. Keep your existing styling inside the wrappers.

Tier and page functions

These functions create roles and page metadata. Import them as sem. Every role reserves its authored geometry, so hiding a role does not cause the remaining page to reflow.

sem.tiers

sem.tiers(preset: none, default: none, ..args)

Declares the page’s tier preset and optional default. It accepts one positional preset or the named preset: form. default: can name a recipe or use the original zero-based recipe index. A page declaration overrides the global TOML default.

#sem.tiers("result", default: "answer")
// Equivalent named form:
#sem.tiers(preset: "result", default: "answer")

sem.hook

Opening question, problem, or attention cue.

sem.hook(body, inline: false, ..x)

sem.cue

Short visible instruction or audience cue. Use sem.note for a presenter note that does not appear in the artwork.

sem.cue(body, inline: false, ..x)

sem.answer

Main answer, explanation, or design content.

sem.answer(body, inline: false, ..x)

sem.detail

Derivation, worked detail, or optional depth.

sem.detail(body, inline: false, ..x)

sem.caveat

Limitation, qualification, uncertainty, or boundary.

sem.caveat(body, inline: false, ..x)

sem.takeaway

Message eligible for extraction and deep-link association. Requires a nonempty string ID.

sem.takeaway(id, body, inline: false, ..x)

sem.contrast

Independent alternative or same-position replacement. The required group string becomes its author ID; placement remains ordinary Typst layout.

sem.contrast(group, body, inline: false, ..x)

sem.support

Evidence or a marked subregion, optionally associated with a takeaway in metadata.

sem.support(body, to: none, inline: false, ..x)

    region: (x: 0.53, y: 0.12, w: 0.40, h: 0.70),

#sem.takeaway("stability")[#pigeon-sem(
  "takeaway",
  [Stability depends on how observations constrain the estimate.],
)]

sem.note

sem.note(body, public: false)

Creates metadata rather than visible artwork. Private notes are presenter notes; public: true notes are included in audience reading and search views. Notes remain in distributed metadata, so private notes are not a confidentiality boundary.

#sem.note[Ask for a prediction before showing the answer.]
#sem.note(public: true)[The question and answer are deliberately separate states.]

sem.deep

sem.deep(target, to: none)

Creates an explicit detour to a labelled physical page. The target is a Typst label such as <derivation>. With to:, the detour is available only when a role with that author ID is visible. Without to:, it is always available on the source page. In Navigate mode, Enter follows the first applicable detour; the HUD can select among several. R restores the saved page, tier, mode, and camera.

#sem.takeaway("variance")[Regularization can trade bias for variance.]
#sem.deep(<derivation>, to: "variance")

// The destination is a physical page with a label.
#pagebreak()
#text(size: 28pt)[Derivation] <derivation>

sem.background

sem.background(default: white)

Returns the authored default fill during ordinary compilation, or the configured tier background during Pigeon’s variant compilation. Use it as the page/theme fill. It creates neither a role nor a background by itself.

#set page(fill: sem.background(default: rgb("#F7FAFC")))
// A recipe may now select: background = "#FFF8E8"

Voice-target functions

Voice markers identify objects for Pigeon’s configured phrase → action rules. They are separate from tier roles, but should normally be nested inside a tier role so hidden objects cannot be targeted.

pigeon-sem

pigeon-sem(target, body, id: none, visible: true)

Marks an explicit voice rectangle around body. target is the configured target name, commonly "_table", "_fig", "_example", or "takeaway". id: supplies an optional object ID, unique within the physical page; otherwise Pigeon generates one. visible: false omits the target without hiding the artwork. Wand uses its own detected regions and shares tier visibility filtering.

#sem.answer[
  #pigeon-sem("_table", table(
    columns: (2fr, 1fr),
    [*Estimator*], [*Variance*],
    [Regularized], [2],
  ))
]

#pigeon-sem("_fig", image("figure.svg", width: 80%), id: "figure-main")
Visibility rule
Voice and Wand only see targets in the current tier. A hidden tier never becomes visible because of a voice phrase.
Marker placement
Wrap the complete decorated body inside the external alignment wrapper. Keep the marker around the whole table, figure, or takeaway artwork.

pigeon-hidden advanced

pigeon-hidden(body)

Hides a body while reserving its layout, and tells nested pigeon-sem markers that their artwork is absent. Use it with existing custom/Touying reveal logic when a plain Typst hide() would retain target metadata. Nested calls are supported. Semantic tiers already track their role ancestry; they do not require this helper.

#import "pigeon-sem.typ": pigeon-sem, pigeon-hidden

#pigeon-hidden[
  #pigeon-sem("_fig", image("optional-figure.svg"))
]
Build switch: --input pigeon-sem=off renders the voice marker body without emitting marker metadata. This is useful for comparing layout, but the normal converter leaves voice markers enabled.

Default voice rules and configurable actions

These are the repository defaults. A deck can replace them in its TOML file. Naming an existing function _table or takeaway alone does not create a voice target; wrap its rendered body with pigeon-sem.

TargetDefault trigger phrasesDefault actionMultiple matches
takeawaykey message(s), takeaway(s), take-away message, takeaway message, take away message, conclusion(s)popstack
_tablethis tablepopask
_figthis figure; this plotpopask
_examplethis examplepopask

pop enlarges the selected artwork; focus isolates it on a navy canvas; spotlight emphasizes its original location. ask offers a choice when several objects match, while stack presents them together. Manual rule buttons and typed phrase tests are also available.

[voice]
enabled = true
backend = "whisper"
lang = "en-US"

# Defining rules replaces the entire default rules collection.
[[voice.rules]]
id = "table"
phrases = ["this table", "compare these results"]
target = "_table"
action = "focus"            # pop | focus | spotlight
multi = "ask"               # ask | stack

Recognition is enabled by default but starts only after an explicit microphone click. Local Whisper needs the generated loopback server and installed helper/model. The optional browser backend uses Chrome’s on-device API. Build with --no-voice to disable recognition while retaining manual actions. Audio/transcripts and transient emphasis are not stored in the presentation or exported documents.

Composition rules

Independent states

Each show selection is complete. A question state can show only hook and a later answer state can show only answer; the answer does not inherit the hook.

Reserved geometry

Hidden role bodies reserve their physical space. This keeps tier navigation, voice rectangles, and ink coordinates stable.

Nested visibility

A hidden ancestor hides descendants. Showing a parent does not reveal a child that its own role selection hides.

One physical page

Role boxes must fit one page. Do not use page-spanning blocks or a reveal wrapper that changes the physical page count.

Opaque replacement

For alternatives in the same position, use ordinary Typst place with opaque blocks in separate role wrappers. Paint order determines which alternative covers the earlier one.

Background override

Opt into per-tier fills with sem.background(default: white) in the page/theme fill. Foreground colors remain authored.

#set page(fill: sem.background(default: white))

#box(width: 100%, height: 140pt)[
  #place(top + left)[
    #sem.answer[#block(width: 100%, height: 120pt, fill: rgb("#EAF0F6"))[Initial claim]]
  ]
  #place(top + left)[
    #sem.contrast("correction")[
      #block(width: 100%, height: 120pt, fill: rgb("#FFF6E7"))[Correction]
    ]
  ]
]

TOML recipes that select semantic states

The Typst functions author roles. The TOML file decides which role combinations become presentation states and how Pigeon navigates them.

[tiers]
mode = "step"              # "slide" or "step"
default_preset = "result"

[[tiers.presets.result]]
name = "question"
show = ["hook", "cue"]

[[tiers.presets.result]]
name = "answer"
show = ["answer", "support", "caveat"]
default = true

[[tiers.presets.result]]
name = "message"
show = ["takeaway"]
fx = "extract"

[[tiers.presets.result]]
name = "full"
show = "*"
pin = "takeaway"
emph = ["support", "contrast"]
dim = ["detail"]
# background = "#FFF8E8"

[[tiers.presets.flat]]
name = "full"
show = "*"
Recipe keyValuesEffect
nameUnique nonempty string within the presetNames the state for the HUD and page defaults. It may differ from a role name.
showRole names or "*"Complete visibility selection; supports hook, cue, answer, detail, caveat, takeaway, contrast, and support.
defaulttrueMarks the recipe used when a page does not specify another default.
emphRole namesOutlines visible role regions.
pinRole names or a roleRings visible regions without revealing hidden content.
dimRole namesDims selected visible roles. A role cannot be both emphasized and dimmed.
fx = "extract"Exact stringCenters visible takeaway(s) and dims the current artwork. A state without a visible takeaway is pruned.
background#RRGGBBUses a page fill only when the Typst page/theme opts into sem.background.
enter = "deep"Exact stringAccepted as a non-visible hook; it is skipped as a presentation state and does not automatically navigate. Author the actual destination with sem.deep.

Omitting presets supplies the built-in result and flat presets. Supplying an explicit presets table replaces that collection, so include flat yourself when you need it.

The built-in result has question (hook, cue), answer (hook, cue, answer), extracted takeaway, and full states. Full is its default, with takeaways pinned, support/contrast emphasized, and detail dimmed. flat has one complete state. The custom example above deliberately changes which roles appear together.

Defaults, pruning, and validation

Default priority is the page’s sem.tiers override, the preset’s default = true, then the last surviving state. Empty states and extraction states without a visible takeaway are pruned, except authored background-only states. Adjacent states with identical visibility and effects collapse. A removed default maps to an earlier surviving state or the first survivor; a duplicate aliases its surviving state. Choosing extraction as the effective default generates a build warning.

[pigeon.tiers] replaces the top-level [tiers] table; [pigeon.voice] similarly replaces [voice]. Unknown keys, unknown roles, missing presets, invalid colors, duplicate state names/defaults, and conflicting emphasis/dimming are build errors. Selections and effects use the eight supported role names, not arbitrary author IDs or CSS selectors.

Runtime behavior

Slide mode

Normal next/previous changes physical pages and enters each page at its default tier.

Step mode

Next/previous walks the surviving tier states before crossing to the next page. Press N to toggle modes.

Direct tier keys

Comma and period always move to the previous/next tier. Shift+PageUp/PageDown swaps navigation granularity.

Detours

Enter follows an applicable sem.deep link. R returns to the saved physical page and tier.

URLs

?mode=step#12.3 addresses physical page 12 and surviving tier 3. Both numbers are one-based in URLs.

Exports

PDF/PNG document exports and overview thumbnails use complete source artwork. Tier effects and transient voice/Wand emphasis are presentation state; document exports also retain ink and inserted boards.

Navigation, history, and sessions retain tier state; semantic detour return restores the saved view. Search and graph evidence use complete document content. Public notes are added to audience reading/search text; private notes are excluded from those views. Search/graph jumps use the normal mode-dependent entry tier, so finding a hidden detail does not automatically reveal it. Inserted boards and PDF-input pages have a single complete state. The HUD offers state buttons, the default marker, detour choice/return, boundaries, and a Bounds debug checkbox. M remains Wand, D remains Diagram, and B toggles blackout without deleting artwork or ink.

Build the marked Typst source

# Run from the repository root; use its current converter.
python3 typst-to-pigeon/scripts/typst_to_pigeon.py /path/to/slides.typ \
  --config /path/to/pigeon.toml --output /path/to/pigeon-slides \
  --mode step --graph local --no-zip

# Then, inside the generated presentation folder:
python3 scripts/serve.py

Distinct visibility filters, backgrounds, and dim backings need extra Typst compilation and SVG assets. The builder reuses shared variants, but more combinations increase build time and bundle size. Existing Touying reveal pages remain separate physical pages; Pigeon does not force handout mode or collapse them.
